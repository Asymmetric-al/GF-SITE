# Core CMS Integration Note

`GF-SITE` is the standalone public website frontend for Global Fellowship. `Asymmetric-al/core` owns Payload CMS v4 administration, content persistence, uploads, editorial workflows, and publication rules.

This repository **does not** install Payload CMS, a database client, an upload backend, or authentication. Per explicit user direction (2026-11-21), latest **Tiptap (`3.35.0`)** packages (`@tiptap/core`, `@tiptap/pm`, `@tiptap/react`, `@tiptap/starter-kit`, `@tiptap/static-renderer`) are pre-installed in `GF-SITE` so any frontend rich-text needs use Tiptap; Core's Payload CMS v4 Lexical editor (`@payloadcms/richtext-lexical`) remains separate and owned by Core. `GF-SITE` installs, runs, typechecks, builds, and passes checks independently of Core.

## Verified Current Behavior in Core

- **Single Payload runtime:** Payload CMS v4 runs only in `apps/admin`, storing CMS tables in the Postgres `cms` schema and authenticating staff via Supabase (`supabase-strategy`).
- **Editorial and media surface:** Admin UI is served at `/web-studio`, with staff REST endpoints at `/web-studio/api/*`. Rich text uses Lexical JSON (`@payloadcms/richtext-lexical`). Media uploads use Vercel Blob in hosted environments and local disk + Sharp (`thumbnail` and `card` variants) when `BLOB_READ_WRITE_TOKEN` is unset. Public media paths serve `/api/media/file/` (transitioning toward `/web-studio/api/media/file/`).
- **Serialized public boundary:** `packages/api/src/cms/public/serialized.ts` defines allowlist-serialized public shapes (`SerializedPublicPage`, `SerializedPublicMedia`, `SerializedPublicNavigation`, `SerializedPublicUpdate`, and 7 typed layout blocks). `SerializedPublicTenantSummary` intentionally exposes `{ slug: string | null }` only (never leaking internal database tenant IDs), so `GF-SITE` requires `CMS_TENANT_ID` in deployment environments to align Next.js `cacheTag` entries with Core's exact `public-cms:tenant:<cmsTenantId>:collection:<collection>:doc:<docId>` invalidation tags.
- **Public HTTP endpoints and cache tags:** `apps/admin` exposes `/api/cms/public/*` routes (`/pages/:slug*`, `/missionary-pages/:id`, `/project-pages/:slug`, `/navigation`, `/updates?limit=N`) behind `PublishedContentReader`. `packages/api/src/cms/public/cache-tags.ts` defines lowercase `[a-z0-9_-]` tags (max 64 chars per segment, max 256 bytes total) and `PUBLIC_CONTENT_CACHE_LIFE_PROFILE = "public-content"`.

## Adopted Future Contracts in Core (Tracked Separately)

Core's architecture records separate shipped Phase-5 behavior from upcoming platform releases:

- **Release-backed reader (ADR-0027 amendment, AL-2688 / ADR-0229):** Publishing will freeze serialized pages into immutable release rows so the public site does not depend on `apps/admin` availability on the read path.
- **Per-request serving admission (Phase 22 D18 / ADR-0135, D21 / ADR-0138):** An uncached admission check keyed by verified host and path decides what may be served before reading cached release bodies. `GF-SITE` already implements this seam on `/projects/:slug` via `src/proxy.ts`.
- **Site, domain-binding, and locale contracts (Phase 24 D66):** Public reads will bind trusted Tenant, environment, Site, stable Site Locale, and exact public generation with CMS fallback disabled.

## Current Content Boundary in GF-SITE (Round 24 Hardened State)

All Core consumption in `GF-SITE` is isolated behind `src/lib/content/` (`server-only`, zero `@asym/*` or Payload imports):

- **`src/lib/content/types.ts`:** Mirrors Core's `SerializedPublicPage`, `SerializedPublicNavigation`, `SerializedPublicUpdate`, `SerializedPublicMedia`, and 7-block `SerializedPublicLayoutBlock` unions, plus discriminated `ContentReadResult<T>` (`found` | `not-found` | `withdrawn` | `unavailable`).
- **`src/lib/content/cache-tags.ts`:** Mirrors Core `packages/api/src/cms/public/cache-tags.ts` segment normalization (`[a-z0-9_-]`, max 64 chars) and `isValidPublicCacheTag` (`<= 256` bytes).
- **`src/lib/content/core-schema.ts`:** Fail-closed validator for all 7 Core blocks, navigation lists, updates lists, `href` sanitization (drops `javascript:`, `data:`, protocol-relative URLs, and control characters), dual-origin media policy (resolving relative Core `/api/media/...` paths against Core `baseOrigin` while allowing absolute media URLs from either `baseOrigin` or `CMS_MEDIA_ORIGIN` over HTTPS outside loopback), dated-year check on `impact-stats`, and required attribution on `testimonial`.
- **`src/lib/content/core-client.ts`:** Shared `fetchCoreJsonEnvelope` helper enforcing `AbortSignal.timeout(3000)`, a streaming WHATWG `WritableStream` `2 MiB` response-body abort guard that distinguishes size-limit aborts from stream errors, explicit `response.body.cancel()` cleanup on error/410 returns, and normalized `found` / `not-found` / `withdrawn` / `unavailable` status mapping across all Core public endpoints.
- **`src/lib/content/core-cached.ts` and `src/lib/content/reader.ts`:** All revocable consent-sensitive endpoints (`readProjectPage`, `readPublicNavigation`, `readPublicUpdates`, and `readMissionaryPage`) run strictly uncached (`cache: "no-store"` with React per-request `cache()` deduplication and `await connection()` inside `<Suspense>`) so both consent withdrawals and in-place redactions take effect on the immediate next request without depending solely on asynchronous webhooks or risking cache-vs-live divergence. General static CMS pages (`readCmsPage` via `readCachedCoreCmsPage`) stay wired on `createContentReader` using Next.js 16 `"use cache"` + `cacheLife("public-content")` + `cacheTag` for future non-revocable general CMS pages while never caching upstream outages.
- **`src/app/(site)/projects/page.tsx`, `src/app/(site)/projects/live/page.tsx`, `src/app/(site)/missionaries/page.tsx`, and `src/app/(site)/missionaries/live/page.tsx`:** When `CMS_BASE_URL` is unset in standalone preview builds, `/projects` and `/missionaries` serve statically prerendered standalone directories (`The Global Fellowship General Fund` featured above 15 standing institutional funds keeping `Where Most Needed` distinct, plus 4 verified public U.S. leadership profiles, zero restricted field workers in Git, native no-JS `<main>`-before-`<footer>` order). Whenever `CMS_BASE_URL` is configured, `src/proxy.ts` rewrites `/projects` internally to `/projects/live` and `/missionaries` internally to `/missionaries/live` (preserving public URLs and emitting zero standing-catalog titles in the initial HTML stream!). Both live directories verify linked `/projects/:slug` and `/missionaries/:id` navigation entries in bounded batches (projects `max 48`, missionaries `max 60`, batch `6`) directly against Core (`readProjectPage` / `readMissionaryPage`) so withdrawing a document in Core hides it immediately even before Core's separate `navigation` document is edited.
- **`src/proxy.ts`, `src/app/(site)/projects/live/[slug]/page.tsx`, `src/app/(site)/missionaries/live/[id]/page.tsx`, `src/lib/http/csp.ts`, `src/lib/content/admission-handoff.ts`, `src/lib/http/standalone-notice-html.ts`, and `unavailable/outage/route.ts`:** Pre-stream serving admission and runtime CSP scoped to `matcher: ["/projects", "/projects/:path*", "/missionaries", "/missionaries/:path*"]` (zero overhead on other routes). Validates decoded project slugs (`/^[a-z0-9-]{1,120}$/u`) and missionary IDs (`/^[a-zA-Z0-9_-]{1,120}$/u`) locally before calling Core. Sets the single authoritative runtime `Content-Security-Policy` header from `buildContentSecurityPolicy()` on every `/projects*` and `/missionaries*` response (while `next.config.ts` sets CSP on all other routes via `"/((?!(?:projects|missionaries)(?:/.*)?$).*)"`), permitting runtime `CMS_BASE_URL` / `CMS_MEDIA_ORIGIN` media and configured `DONOR_APP_BASE_URL` `form-action` origins without double-CSP intersection even after zero-CMS builds. When `CMS_BASE_URL` is unset, standing routes pass straight through to statically prerendered pages with zero `await connection()` and zero deferred streaming templates. When Core is connected, `proxy.ts` strips any incoming `x-gf-admission-token`, registers a single-use, scope-checked, bounded (max 64 entries, 5-second TTL) in-memory handoff token paired with a stateless HMAC-SHA256 signature (`CMS_REVALIDATE_SECRET`) for multi-instance serverless portability, and internally rewrites admitted live requests to `/projects/live`, `/projects/live/:slug`, `/missionaries/live`, or `/missionaries/live/:id` (preserving public URLs and rendering detail pages in **one** Core HTTP call on warm same-instance requests). Missing or withdrawn entries rewrite to prerendered 404 routes (`/projects/unavailable/not-found` and `/missionaries/unavailable/not-found`, zero slug/ID echo). Upstream Core outages or invalid config rewrite to genuine HTTP `503 Service Unavailable` (`Retry-After: 60`, `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow`) via accessible standalone HTML (`renderStandaloneNoticeHtml` using locally vendored `Source Serif 4` and `Nunito` from `public/fonts/`).
- **`src/lib/giving/checkout-handoff.ts`, `src/lib/giving/checkout-summary.ts`, `src/lib/giving/standalone-gift-html.ts`, `src/app/checkout/route.ts`, `src/app/give/checkout/route.ts`, `src/app/donor-dashboard/**`, `src/app/login/route.ts`, `src/components/interactive/quick-give-input.tsx`, and `src/components/interactive/giving-handoff-widget.tsx`:** Plumbs public giving directly into `Asymmetric-al/core`'s Donor Application (`apps/donor`, with zero Every.org dependencies or fallbacks) while strictly honoring Core's PostgreSQL UUID payment contract (`packages/api/src/donate/begin-gift-intake.ts` requires UUID-formatted `p_fund_id` / `p_missionary_id`, while `packages/lib/payments/checkout-designations.ts` recognizes `general` as the general-fund alias). One shared server-side recipient state machine (`classifyCheckoutDesignation()` + `resolveAuthoritativeCheckoutRequest()`) binds displayed recipient, payment target, and Finance inquiry together: General Fund aliases (`general`, `general-fund`, or genuinely unspecified bare checkout) normalize to `fund=general` (`The Global Fellowship General Fund`), UUID-formatted IDs (and optional `CORE_DONATION_ID_MAP` env UUID mappings) route to Core only when one-time and when any paired `workerId` + `missionary_id` matches identically or through `CORE_DONATION_ID_MAP`, and unverified `workerId`+UUID pairs, blank, malformed, conflicting, or unknown standalone slugs normalize to `designation_status=unresolved` across every redirect, HTTP `400` retry, and cadence change so donor intent is never silently downgraded to General Fund or displayed under a mismatched profile name. `isOnlineCheckoutEligible()` requires both a configured `DONOR_APP_BASE_URL` and an eligible target before showing online-checkout status copy or routing directly to Core checkout (while directory cards and detail widgets keep concise `"Give"` / `"Give $100"` action labels per stakeholder direction). Unmapped standing designations, monthly requests, and unresolved links route synchronously to `/give/checkout` (`src/app/give/checkout/route.ts`, a zero-JS Brand-Kit HTML Route Handler with `<main id="main-content">` strictly before `<footer>`) handling all four states honestly (`Continue to online checkout` with `"Continue to donor sign-in"`, `Start a monthly gift`, `Arrange your designated gift`, and `Confirm your gift designation`) with `"Email Finance"` actions, opaque UUID `Designation reference` lines when a UUID is present, and pre-filled `mailto:` bodies. All routes enforce one exact-cent `$1.00` to `$1,000,000.00` validator (`parseGivingAmount`, accepting comma-grouped thousands such as `1,250.50`), return accessible HTTP `400` server correction forms (with skip link and flex footer) on invalid non-blank queries, and use same-origin HTTP `200` meta-refresh + link handoff on native `via=form` submits so Chromium and WebKit `form-action 'self'` CSP never blocks cross-origin redirects without JS.
- **`src/lib/content/lexical-renderer.tsx` and `src/components/cms/cms-block-renderer.tsx`:** Pure server-side allowlist renderer for Payload Lexical JSON (zero `dangerouslySetInnerHTML`, `horizontalrule` separator support, configurable `minHeadingLevel`), enforces single semantic `<h1>`, strictly honors `legacyContentFallback === true`, puts `<dt>` before `<dd>`, displays `ExternalLinkIcon` on new-tab CMS actions, drops informative CMS images missing `alt` text, and renders remote Core media directly (`unoptimized`) while `next.config.ts` restricts `/_next/image` to local `/photos/**` and `/brand/**` assets only.
